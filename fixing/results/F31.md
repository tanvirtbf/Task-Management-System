## 1. Standing the harness up — an environment archaeology

The 13 `.pw.ts` specs were written in P45/P46 and never ran in this campaign. Standing them up
required reconstructing their world:

- **They run against `taskmanagement_qa`, not dev** — four specs shell into that DB by name, and
  `tasks-views` pins task ids as string constants. The :5501 API is booted with
  `DB_NAME_OVERRIDE=taskmanagement_qa` for e2e work.
- **The pinned fixtures were gone** — the three P45X tasks (ids hardcoded in specs) and the
  "P46 KI-13 bug" the /eng spec clicks by name had been cleaned away since P46.
  `fixing/evidence/F31/restore-qa-fixtures.cjs` reconstructs them idempotently, including the two
  subtleties runs 1–2 exposed: GAMMA needs `sla_due_at` stamped (a direct INSERT bypasses
  `computeSlaDueAt`, and the Bug-drawer spec asserts the SLA panel, which only renders when set),
  and the Bug Triage list needs at least one live bug or `/eng` cannot resolve it.

## 3. What the harness taught (the reusable part)

- **The view tabs are code-split (F30), and the LIST stays mounted while a chunk loads.** A text
  locator happily matches the list's rows during the transition — run 1 spent two tests dragging an
  undraggable list ROW and reading "the drag does nothing". The fix is `openBoard()`/`openCalendar()`
  helpers that wait for view-specific DOM (columns side-by-side / a `day-*` grid cell) before
  measuring anything. Any future spec that clicks a view tab must use them.
- **dnd-kit + Playwright works fine** once the right element is under the pointer: manual
  `mouse.down → jiggle past the 4px activation constraint → stepped move → up`, dropping onto a
  card in the target column (`over` resolution handles both `column:` ids and task ids).
- The diagnosis method is kept in the results rather than the tree: a one-off debug spec that
  screenshotted mid-drag and counted DragOverlay copies — the screenshot showed the list view
  still on screen with the URL already at `/board`, which was the entire story.
