# F21 — Activity and audit quality (ISS-049 · ISS-061 · ISS-062)

**Status:** DONE
**Fixes:** all three
**Risk taken:** 🟢 — audit rows say more and lie less; one client component
**Gate:** `tasks` + `collab` in the consolidated run · client vitest **44/44**
**Data left behind:** none

---

**ISS-049 — the log records VALUES now, and no-ops are silent.** `task_updated` context was
`{"fields":["name"]}` — which keys, never which values — and a PATCH that changed nothing still
wrote a row. Now `scalarChanges()` diffs the patch against the current row: per-field
`{from, to}` in wire names, a no-op writes **no row**, and a status-only PATCH writes only its
`status_changed` row (the one action that always did this properly — it was the model). **Bulk got
the same honesty:** each target's row diffs against ITS OWN pre-update values, and a target the
patch does not actually change gets no row — a 200-task bulk no longer leaves 200 rows saying
`{"bulk":true}`. (First cut leaked the bulk meta-flag `archived_at_provided` into the diff; the
probe caught it and meta/membership keys are excluded.)

**ISS-062 — checklists leave a trace.** Create/delete of a checklist and add/delete of an item now
write activity rows — and the DELETE rows carry the **name/text**, because the row itself is gone
and the trace is the only place it survives. "Who deleted the acceptance criteria?" is answerable:
`checklist_deleted {name: "F21 acceptance criteria"}`. Four service inputs gained `actorId` (the
create/delete paths never carried the actor because they never recorded anything).

**ISS-061 — the drawer speaks the server's language.** The client switch was written against the
MOCK API: 7 of its 9 cases were codes the server never emits (`branch_created`, `pr_opened`…), and
11 of 13 real codes rendered as raw snake_case. Replaced with a 27-entry map verified against every
`task_activity` writer in `server/src` (the probe re-derives the emitted set from source and fails
if any code lacks a rendering — so the NEXT drift gets caught too). Context rendering now shows the
load-bearing bit: changed field names for `task_updated`, the checklist name/text, the review
status — instead of reading only a `taskName` key that task activity never contains.

Evidence: `f21-probe.cjs` / `.txt` — 12 checks incl. the source-derived vocabulary parity, exit 0.
