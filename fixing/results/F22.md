## 1. ISS-011 — three §32 promises, now kept

- **`tag.in_use` (409).** Deleting a tag that is still on tasks used to 204 and silently strip it
  from every task (the FK cascade) — categorisation data lost with no warning. Now refused with the
  count; an unused tag still deletes.
- **`task.cannot_complete_blocked` (409).** A `blocks` dependency was decoration: the blocked task
  moved to Done regardless. Now both the single PATCH and the BULK path (fail-atomic, like every
  other bulk validation) refuse while `openBlockerCount > 0` — an open, non-archived blocker on a
  not-done status. Complete the blocker and the same PATCH succeeds.
- **`sprint.overlap` (409).** Two overlapping sprints made "which sprint is this week?" ambiguous.
  Create and date-changing update both check `[start,end]` intersection (self excluded on update);
  back-to-back ranges stay legal.

## 2. ISS-019 — headship SURVIVES deactivation

`deactivate` called `clearHeadships` — silently, permanently, with no audit row, and reactivation
did not restore it (P4: Marketing orphaned; the weekly HR report generated headless). The issue's
Expected line offers "headship survives (and is restored on reactivate)" — and the cheapest correct
reading is to **stop clearing**: a deactivated head cannot log in anyway (F10 revokes every
session), so the pointer costs nothing, a returning head finds their department intact, and
replacing them remains a one-PATCH admin act. The old code's comment ("Reactivation deliberately
does NOT restore") described exactly the behaviour ISS-019 documents as harmful.

## 3. ISS-020 — the last-admin backstop

`role.last_admin` existed only on the dynamic-RBAC path. The legacy paths (role PATCH, deactivate)
now refuse any transition that would leave **zero active admin-capable accounts** (role
owner|admin). Honestly stated: while an active owner exists the guard is unreachable — the owner
cannot be demoted or deactivated (guards that predate this phase), and an owner who can still log
in can always fix things, which is the issue's own "nobody able to fix it" rationale inverted. The
backstop protects the workspace whose owner is NOT active (imports, hand edits) — and the probe
proves it fires by forcing exactly that state and restoring it.

## 4. ISS-034 / ISS-051 — the archived-state machine, applied evenly

Lists were the model (always frozen). Now: **PATCH an archived space → 409 `space.archived`**
(renaming/re-heading a thing the workspace put away was silent mutation); **comment on an archived
task → 409 `task.archived`**; **a dependency edge with an archived endpoint → 409** (the P18 update
to ISS-051 — edges onto archived tasks rendered on live tasks' lists). Unarchive first and every
one of those works.
