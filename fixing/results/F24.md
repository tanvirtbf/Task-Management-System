# F24 — Home page honesty (ISS-057 · ISS-056 · ISS-059)

**Status:** DONE
**Fixes:** all three
**Risk taken:** 🟢 — two fabricated signals removed, one metric repointed
**Gate:** client `vitest` · jest `home` · **the six KPI numbers re-verified against hand-written SQL**
**Data left behind:** none — the probe is read-only

---

## 1. ISS-057 — two fabricated signals around a correct number

The six values were always right (P19 recomputed all six by hand for four accounts). What surrounded
them was not:

- **The trend badge was hardcoded.** `buildKpi` returned `trend: 0, trendDirection: "flat",
  isPositive: false` with the comment *"V1 computes no trend (mock parity)"*, and the card rendered
  that as a permanent **"— 0.0%"** — which reads as a *measured* "no change since last period",
  not as "not computed".
- **The sparkline did not plot the metric.** It bucketed the currently-matching tasks by
  `DATE(created_at)`, so it was a creation-date histogram: **"Open Team Tasks 31"** sat above a line
  summing to **4**.

**Both are gone**, server and client — the wire `HomeKpi` is now `label` + `value` + `valueDisplay`
and nothing else. A real trend needs task *status history*, which is not stored; inventing one in
the meantime is what this issue is about, so it stays unbuilt (a note for F28's backlog).

The per-tile accent colour that used to tint the sparkline now tints the **number**, so each
caller's intent — danger for Overdue and SLA, success for the team total — survives without carrying
any invented data.

## 2. ISS-059 — the tile counted GitHub PRs

"Awaiting My Review" counted `reviewer_id = me AND pr_status = 'open'`. `pr_status` is NULL on every
task in the database, so the tile read **0 for everyone, permanently** — while the review workflow
the product actually shipped (a department head approves or flags a completed task) had real work
waiting.

It now counts what a head would expect: a **completed task, not yet reviewed** (`review_status IS
NULL` — the enum has no pending state; a row appears only once the head acts) in a space **they
head**. The per-task `reviewer_id` arm is kept, so an explicitly named reviewer still sees their own
queue. Proof: `pr_status='open'` is still 0 rows workspace-wide, the real queue is not, and a
department head's tile is now non-zero.

## 3. ISS-056 — the Agenda card invented a time of day

`formatTime(due_date)` on a **DATE** column: `new Date("2026-07-30")` parses as UTC midnight, so the
"time" was really the viewer's offset from it — "6:00 AM" in Dhaka, "12:00 AM" in UTC, "8:00 PM the
previous day" in New York. And because every row carried the same instant, the sort by it was a
no-op.

`tasks` has no time-of-day column anywhere, so there is no time to show. The column now carries the
task's **priority**, and the list sorts by it (urgent first, then name) — a sort that actually
orders the day.

## 4. The regression that mattered most: the numbers

A change to `HomeRepo` and `HomeService` could quietly break the six values this issue explicitly
says are correct. The probe therefore recomputes `myTasks`, `dueToday`, `overdue` and
`awaitingReview` in independent SQL for **two accounts** (the owner and a department head) and
compares them to the wire. All eight comparisons match — including the new
`awaitingReview` definition, checked against its own SQL.
