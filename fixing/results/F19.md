## 1. The decisions, executed exactly (D6–D8, fixing/DECISIONS.md)

**D6 — build 2, remove 5.** `comment` and `status_change` got real producers. The five that left the
enum — `due_soon`, `overdue`, `automation_failed`, `pr_review`, `incident_alert` — had no producer
anywhere and no surface to build one from (no scheduler, no automations, no review-request flow); a
declared type nothing can ever produce is the lie ISS-072 documents. `009` deletes any rows of the
removed types first (an enum cannot shrink over live values), shrinks BOTH type columns, and drops
`email_enabled`.

**D7 — preferences are real, enforced at ONE chokepoint.** `NotificationsRepo.createMany` now drops
any recipient whose `user_notification_prefs` row for that type has `in_app_enabled=false` — so all
seven producers (and every future one) obey preferences without eight call-site edits. A missing row
still means "on".

**D8 — the email channel is gone.** `email_enabled` promised delivery that had no implementation
(MailService sends exactly two transactional mails). Removed from the column, the repo, the
controller, the serializer, the validator (a body still carrying it gets a 422 that says why), and
the client's typed api.

## 2. The two new producers

- **`comment` (ISS-064):** a plain comment now notifies the people ATTACHED to the task — assignees
  + watchers, minus the author, minus anyone already notified as `mentioned` (one event, one
  notification). Before this the watcher feature maintained rows nothing ever read.
- **`status_change`:** assignees + watchers minus the actor, title `moved "<task>" to <status>`.

## 3. Proof (`f19-probe.txt`, 23/23 — delta-counted)

Enum verified 7/7 with the five gone; `email_enabled` gone from the column and the wire; PUT with
`email_enabled` → 422 naming the removal; PUT with a removed type → 422. A plain comment notifies
assignee + watcher, not the author; a mentioned watcher gets `mentioned` only, never both. A status
change notifies both, not the actor. **Suppression proven live:** arif turns `comment` off → a new
comment delivers to the watcher and NOT arif; toggled back on, it flows again. **All seven surviving
types produced live**, including `report_ready` via the real weekly job (one report slot freed
first, so the regeneration both proves the producer and restores the 12-report baseline).

## 4. A probe lesson that cost a re-run

The first probe filtered counts on a bound JS-Date timestamp and misread same-second rows — 11
false FAILs against perfectly-working producers, and its cleanup (same predicate) left 7 rows and
deleted 6 baseline reports. Rewritten to **delta counting** (count before, produce, count after —
no timestamps anywhere) with id-anchored cleanup; the damaged baseline was restored by re-running
the report job. Recorded because timestamp-bound assertions keep being the wrong tool.
