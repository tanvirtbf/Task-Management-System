## 1. One family, one pattern

All three were read paths that skipped the space filter the codebase already implements everywhere
else (`listScopeFilter` / `spaceScopeFilter`, the SearchRepo/P25 pattern). The fixes are three
applications of that existing pattern — no new machinery, no schema, no grant changes.

### ISS-053 — dependency hydration (and unlink)

`TaskDependenciesRepo.findTaskRowsByIds` — the "other end" hydration — now carries
`listScopeFilter(tasks.primaryListId, taskOwnEscape())`. An invisible other end simply does not
hydrate, and the service's existing defensive drop (`toView` → null) removes the edge from the
response. The **unlink** hole closed with it: `delete` resolves both endpoints through the same
filtered read — fewer than two rows means one end is invisible, and the edge "does not exist" for
that caller (404, D-9's no-existence-oracle rule; the create path already behaved this way).

### ISS-060 — the audit feed

`WorkspaceActivityRepo` gained `auditVisibility()`, AND-ed into `listRecent`, `listFeed` and
`countFeed`. What a row is **about** decides who reads it:

| rows | visible to |
|---|---|
| `space` / `list` | anyone whose space visibility covers them (the same rule as every other read) |
| `user`, `role`, `workspace`, and the workspace-wide catalogs (`task_type`, `tag`, `custom_field`, `sprint`) | **owner/admin only** — people-management and configuration history is audit material |

A space-narrowed *admin* keeps the admin-material rows plus their spaces. Non-request contexts
(jobs, direct-repo unit tests) and full-sight admins see everything — `undefined` filter, matching
`visibilityScope`'s own defaults. The F7 gate (`activity.view`) still fronts the route; this is the
**data** half ISS-060 filed separately.

### ISS-084 — forms

`FormsRepo.findByIdInWorkspace` + `listByWorkspace` carry `listScopeFilter(forms.listId)`. The
per-list route was already scoped, every write was already gated, and the anonymous public path
resolves by slug and is untouched.

## 3. Notes

- **The one behavioural change for seeded roles is the ISS-060 fix itself:** members and guests no
  longer read the HR/audit timeline. That is the issue's Expected line, not a side effect. Space
  and list history stays visible to them (their space visibility is workspace-wide today).
- **`workspaceActivity` jest went 41/41 untouched** — its member-role tests only ever asserted
  space/list rows (the catalog-row seeds were filter-test foils), so the new rule matched the
  existing spec exactly.
- **The `taskdeps` chain-run failure was load-flake**, not a regression: the gate chain started
  while the probe API still held its pool; the solo re-run is 67/67. Same protocol note as the
  dept-review-era "load-flake" entries.
- `GET /activity` for the two seeded dept-only accounts answers **403 at the F7 gate** (they hold no
  `activity.view`), so the scoping here is exercised via the probe user whose custom role does.
