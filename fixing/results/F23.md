## 1. ISS-007 — `limit` is real on the four §1 endpoints

`/lists`, `/spaces`, `/tags`, `/task-types` returned every row with `has_more: false` no matter
what. A shared `paginateArray` (utils/pagination.ts) now slices the position-ordered sets with the
§1 default/max (100/200), a truthful `has_more`, and a working opaque offset cursor — without
teaching four small repos keyset pagination they do not need. Proof: `?limit=2` returns 2 +
cursor; following the cursor pages **without overlap**; `limit=0` is 422.

## 2. ISS-008 — every cursor the server did not issue is a 400

`garbage` is base64url-alphabet, so the lenient decode produced mojibake that silently restarted
pagination at page 1 *with a fresh next_cursor* — a retrying client looped forever; a tampered
`<cursor>XX` shifted the window. `strictDecodeCursor` (round-trip byte-exact + printable-ASCII) now
backs **all six decoders** (users, workspace-activity, task-activity, forms, notifications, and the
new offset cursors), and users additionally enforces its id-shape (printable junk that round-trips
is still foreign). Proof: six foreign-cursor forms → `400 pagination.invalid_cursor`; an issued
cursor still works.

## 3. ISS-014 — a mistyped filter is a 422, not the full set

`/users?search=zzzz` returned all rows (the real filter is `q`). An `allowQuery` middleware now
refuses unknown query parameters, naming the parameter AND the accepted set. **Scope, honestly:**
applied to the five primary collection endpoints (`/users`, `/spaces`, `/lists`, `/tags`,
`/task-types`) — the issue's evidence surface plus the four F23 touched anyway. Extending it to
every list endpoint is mechanical (the middleware takes the route's own set) and left for the F32
sweep rather than done big-bang here.

## 4. ISS-067 / ISS-040 / ISS-048 — silence became answers

- **Checklist-item PATCH is a closed set.** `{is_completed: true}` answered 200 and did nothing —
  the obvious way for any new client or the AI assistant to tick a box. Now 422 pointing at
  `POST /checklist-items/:id/toggle`; any unknown field 422s naming the accepted set; the DB row
  proves nothing was silently set.
- **POST refuses what PATCH refuses** (task types): `is_system`/`position` on create were silently
  dropped (stored `is_system=0` behind a 201). Now 422 "server-owned". The spaces half of ISS-040
  was already closed in F18.
- **Misdirected task-PATCH fields get real answers.** `{assignees}` used to produce "Provide at
  least one field to update" — you sent a field and were told you sent none. Now the 422 names the
  right door (`POST /tasks/:id/assignees`, the tags endpoints, parent is create-only); a genuinely
  empty body keeps the old message.

## 5. ISS-012 / ISS-010 — the documentation stops lying (D10)

- §1 documents the **four response families** as deliberate exceptions with reasons;
  `/activity/recent`'s spec — the one true spec-vs-code contradiction — now says `{data}` (what the
  server always returned and the client reads). D10: re-shaping working endpoints would break the
  only client for zero functional gain.
- §32 regenerated **from the code**: 129 distinct codes (the table documented 37 while the server
  threw 140 — and several "documented but never thrown" codes became real in F22: `tag.in_use`,
  `task.cannot_complete_blocked`, `sprint.overlap`, `role.last_admin`). The generator ships as
  evidence (`regen-catalog.cjs`) so the catalog can be re-derived after any change; a curated
  meanings table for the load-bearing codes follows the generated list.

## 6. Thirteen stale specs updated, and a gate lesson

The consolidated run surfaced 13 specs across five suites that asserted the OLD contracts — most of
them pinning a defect as intended behaviour:

| suite | what it asserted | now |
|---|---|---|
| `tags/delete` ×3 | deleting an IN-USE tag 204s and strips it from every task — ISS-011a verbatim, and its describe block called it *"the §9 headline behavior"* | 409 `tag.in_use`; the detach-then-delete path is tested instead |
| `spaces/update` | an archived space stays fully editable (ISS-034 verbatim) | 409 `space.archived` |
| `tags/list`, `task-types/list`, `spaces/list` (7 specs) | `limit`/`cursor`/unknown params silently ignored; a large set comes back uncapped (ISS-007/008/014 verbatim) | real paging, 400 on foreign cursors, 422 naming unknown params |
| `task-types/create` | `is_system` accepted and silently dropped (ISS-040 verbatim) | 422 "server-owned"; a stray unknown key is still just ignored |
| `users/list` ×2 | `?workspace_id` silently ignored; a 10 000-char cursor "survives" | 422 / 400 — refusing is strictly stronger than ignoring |
| `sprints/create` | the duplicate-name fixture reused identical DATES | disjoint dates, so the NAME rule is what it isolates |

**A gate lesson worth writing down.** A 16-module serial jest chain on one box produces spurious
mass-failures once earlier modules leave the connection pool draining — `taskdeps` reported 27
failed in-chain and **67/67 solo**; `sprints` 117 failed in-chain and **150/150 solo**. Every module
was re-measured solo, and that is the number this phase stands on. All 16 green: `gate-final2.txt`.
