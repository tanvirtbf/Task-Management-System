## 2. The proof — every toggle is real

**`f7-enforcement-probe.txt` (exit 0)** — the P5 two-pass design, re-run:

- **Phase A, 17/17 ENFORCED.** A probe user holding one custom role: minimal grants → **403** on
  every gated surface; +the key → through (2xx, or the domain's own 404/409/422 — the request
  reached domain logic). P5's headline **"NOT ENFORCED: 21" is now 0.**
- **Phase B, the composes.** `task.delete_hard` toggle OFF refuses a *legacy admin* (the inert
  toggle of ISS-024 is dead), ON deletes; **compose cannot widen** — a legacy member holding both
  `task.delete` and `task.delete_hard` grants is still refused; `comment.delete_any`,
  `member.edit_profile` (self stays free), `space.head_assign` (general edit unaffected) all toggle
  both ways; `report.view` OFF drops an admin to the head-scoped fallback (empty list + 403 direct
  read) and ON shows all 12 department reports — while **a department head with no `report.view`
  still reads their own dept's reports** (the F6 refinement that kept dept-review alive).
- `attachment.delete_any` is the same one-line compose as `comment.delete_any`; its behavioural
  coverage rides the `attachments` jest module in the gate (R2 round-tripping made a live probe
  disproportionate). Stated, not hidden.

**`f7-day-in-the-life.txt` — 47/47** (a superset of P39's 22 lines, same eight scenarios, same
cast): the CS public-form complaint end-to-end (submit → assign → mention-notify → attach →
resolve → approve, counters exact), O&F checklist/subtask/cross-space dependency, Marketing

## 3. Honest notes

- **My gate script double-applied 25 sites** on its second run (the re-run guard matched on the
  wrong precondition). Functionally harmless — the same middleware twice — but sloppy; deduped, and
  the jest gate was **restarted from scratch on the final tree** per the F3 straddle rule.
- **The day-in-the-life first run failed 22 steps — none were regressions.** One by one they were
  my script's contract guesses (checklists want `name`/`texts`, dependencies want `type`, templates
  want `type`+`structure`+a `taskTypeId` when the list has no default, sprints want `task_ids`) and
  one miscast: P39's "CS head publishes a form" ran under `form.manage`, a **pre-existing**
  admin-only gate F7 never touched — the CS head is a legacy member and could not have done it on
  the old tree either. The final run is 47/47 with zero product changes in between.
- **`form.view_submissions`'s with-grant pass returns 404** (probed against a fake form id on
  purpose): the real endpoint still 500s on the dev DB until F17 closes ISS-025. The *gate* is
  proven (403 → non-403); the endpoint behind it is F17's problem.
